# Rysen Explorer 本机使用说明

本目录使用已安装的 **wslc** 和 `rysen_system:latest` 镜像。脚本只管理现有 `rysen_explorer`、`rysen_backend` 两个容器，不启动 Ubuntu 发行版，不安装 Docker，不重新导入镜像，也不重建或删除容器。

## 启动与停止

在 **Windows PowerShell / PowerShell** 中执行，不要在容器内的 `root@...` Bash 提示符中执行。脚本可从任意工作目录运行。

```powershell
& D:\Dev\wslc\Start-Rysen.ps1
& D:\Dev\wslc\Stop-Rysen.ps1
```

启动会先检查两个容器，再启动尚未运行的容器，修正网页 API 为当前页面地址，并检查 HTTP 配置文件及 Foxglove WebSocket 握手。已运行的容器会保留；启动失败时，只尝试停止本次启动的容器。默认就绪等待为 45 秒，可使用 `-TimeoutSeconds 90` 调整。

停止会依次关闭前端、通知 ROS launch 退出并停止后端，默认每个容器最多等待 30 秒。可重复执行。单个服务停止失败时仍会尝试停止另一个，最后报告错误。退出码 137 表示发生强制终止，不能据此认定设备已下电。

脚本不会自动连接机械手、上电或播放动作。完成后端修改后如需验证完整启动流程，先确认设备已下电、工作区清空，再启动测试。

## 页面与网络

- 网页：<http://127.0.0.1:8080>；默认账号 `admin`，默认密码 `yszn123456`。
- 后端：`ws://127.0.0.1:8765`，此镜像使用 `foxglove.sdk.v1` 子协议。
- 左手 IP：`192.168.0.102`；本机有线网卡：`192.168.0.50/24`。
- 设备 TCP 端口：5856、5857。服务就绪检查不代表机械手已经连接或可以运动。
- 当前容器端口绑定到本机回环地址，仅供本机使用。请勿直接照搬官方 Linux 的 host 网络配置到 wslc。
- 修改网页配置后用 **Ctrl+F5** 强制刷新，避免缓存旧的 API 地址。

`configure-rysen-web.py` 会将 API 基地址改为网页当前 origin（包含 8080 端口）。首次修改的备份位于前端容器 `/workspace/fastApi/public/config/config.js.before-wslc-8080.bak`。每次启动都会检查配置，未知文件格式会报错而不是盲目修改。

## 真机与动作注意事项

1. 真机播放前确认周围无人员手指、线缆或障碍物，机械手安装牢固，停止方式可随时操作。
2. 正常结束时先在页面暂停动作、关闭循环、下电并断开设备，再运行停止脚本。停止容器不是设备急停，也不保证硬件下电；异常情况按设备手册使用物理停止/断电方式。
3. 自定义动作：`D:\Dev\wslc\motions\left-hand-hello.json`。在“动作编排 → 导入 JSON”中选择文件。
4. 该动作约 25 秒、14 个关键帧：张手、四指依次屈伸、四指轻弯、张手；拇指保持零位，单次播放，平滑插值。它是位置动作，不是力控抓取，不要用于夹持物体。
5. 文件已做结构、时间顺序和数值检查，**尚未真机验证**。先断开设备预览，再低倍速、单次试运行。零位和“小角度”也不能保证所有硬件状态下无碰撞。
6. 当前网页导入逻辑可能忽略文件中的 `maxJointSpeedDegS` 字段；不要把该字段当作可靠的硬件限速。以界面实际播放倍速及设备速度参数为准。
7. 导入文件可能替换当前编排，先导出需要保留的动作。网页导入动作时，连接状态下可能同步到 ROS 后端；需要纯预览时先断开设备。

## 数据与排查

停止/启动保留容器内修改，但现有容器没有外部数据卷；删除或重建容器会丢失其内部配置、日志和未导出的数据。动作文件保存在本机 `motions` 目录，需保留。更换镜像前先导出重要编排和日志。

```powershell
wslc container list --all
wslc logs --tail 80 rysen_explorer
wslc logs --tail 80 rysen_backend
```

- 找不到容器：核对 wslc 会话及容器名称；脚本不会自动重建。
- 登录失败：先确认网页地址为 8080 端口、强制刷新，并查看前端日志。
- 页面能打开但后端离线：查看后端日志、8765 端口和 WebSocket 协议。
- 无法连接左手：检查网线、设备电源、192.168.0.x 网段及 TCP 5856/5857；不要为此关闭全部防火墙。
- 若系统执行策略阻止脚本，可检查脚本内容后，对本次 PowerShell 进程使用 `Set-ExecutionPolicy -Scope Process Bypass`，无需永久修改全局策略。
