# MediaPipe ＋ D435 逐指深度约束

完整的个人标定、URDF 解算和实机控制现在使用 **Start-DepthFollow.cmd / Stop-DepthFollow.cmd**，页面 8090；见 [全链路使用说明](../hand-tracking/README-D435.md)。本文的 Start-DepthHand/8095 仍作为独立诊断入口，不能与全链路同时占用 D435。

8090 当前采用两步标定、图像主导固定骨长关节链和直接角度拇指，关闭旧逐点 Z 优化；本文 8095 仍展示下述逐点融合算法，用于独立诊断，不能把两页视为同一控制解算结果。

这是独立 Windows uv 预览项目，页面为 http://127.0.0.1:8095/ 。只读取 D435；没有 SDK、机械手连接或控制输出。现有 A/B 标定与实机跟随代码未修改。

## 启动与操作

1. 用 USB 3 数据线连接 D435，关闭其他占用相机的程序。
2. 双击工作区根目录 **Start-DepthHand.cmd**。依赖由 uv 按锁文件管理；首次启动准备官方 MediaPipe Hand Landmarker 模型，优先复用工作区中校验通过的模型。模型在本机推理。
3. 页面应显示“D435 · MediaPipe ＋ 逐指深度约束”。先将完整的一只手放在约 0.4–0.8 米处，掌心朝向相机，自然展开、手指适度分开。当前一次识别一只手。
4. 点击“重新建立骨长参考”，保持自然展开约 30 个有效帧。参考来自模型骨长和当前掌部尺度的稳健统计，既不是精确骨长测量，也不是关节零位标定。前 30 个合格帧逐步更新，之后冻结；换人、重新进入、相机恢复或重启会重建。暂不保存个人档案。
5. 缓慢屈伸四指、拇指外展和弯曲，再试对指。观察左右骨架、各关节颜色与角度表。拖动骨架可同步旋转视角；两图均以腕部为原点、使用相同比例。
6. **绿色**：该点附近有通过筛选的表面深度，参与约束。**黄色**：缺失、轮廓、背景或时间差问题，依赖模型估计。绿色仍不表示关节中心已直接测量。
7. 左右手标签不符合实际时用“切换左右手标签”；它只修改标签并重建参考，不镜像坐标或控制方向。
8. 暂停用“暂停并释放相机”；恢复用“恢复 / 重试相机”。结束双击 **Stop-DepthHand.cmd**，也可使用 Stop-DepthCamera.cmd。关闭网页不会停止服务。

两种 D435 入口共用 8095 和相机：Start-DepthCamera 是基础测距模式，Start-DepthHand 是手部融合模式。启动另一种模式会停止原模式并切换；相同模式重复启动会复用。修改后端后加 `-Restart`；页面改动刷新即可。

```powershell
& D:\Dev\wslc\Start-DepthHand.ps1 -NoBrowser
& D:\Dev\wslc\Start-DepthHand.ps1 -Restart -NoBrowser
& D:\Dev\wslc\Stop-DepthCamera.ps1

cd D:\Dev\wslc\realsense-tools
uv run --frozen python -m unittest -v
```

## 实际怎样使用深度

MediaPipe 提供 21 个二维关键点和相对三维骨架。将深度对齐到 RGB 后，使用相机内参建立每个关键点的反投影射线，优化每个点沿射线的 Z；因此融合结果仍投影到对应 RGB 关键点。非零畸变参数通过 RealSense SDK 反投影处理。

每点读取 5×5 邻域，筛除零深度、0.12–2 米以外的值及明显偏离模型手部深度的值。至少 9 个像素满足条件，且深度分布没有明显混合表面，才接受邻域中位深度。彩色与深度时间戳差超过 25 ms 时不接受该帧深度约束；该门限是工程初值，不代表硬件同步验证。

联合目标包含骨长、模型相对 Z、可靠深度区间、腕部锚定及弱时序约束，采用鲁棒最小二乘。深度测量的是皮肤表面；目前允许中心相对表面约 −3～+9/12/18 mm 的区间，分别对应指尖、普通点和掌部。这些是可调整的初始假设，不是操作者已标定的皮肤厚度。

可靠掌部深度不足时最多短暂沿用 250 ms 的尺度与锚点；超过后停止输出融合三维骨架并提示等待。完全丢手或帧过期会清空显示，不用固定距离补深度。短暂没有部分手指深度时，仍可输出带黄色来源标记的模型约束结果。

## 怎么判断改进是否有效

- 先看各指有多少绿色点，再比较两图在手掌前后移动、四指弯曲、拇指对指时的连续性。识别耗时和深度约束数量会实时显示。
- 骨长残差是内部一致性指标，不能当作真实空间精度。FUSED 表示至少 5 点通过深度筛选且骨长 P95 残差低于 15 mm；MODEL_ASSISTED 表示当前更依赖模型，两者均不等于精度合格认证。
- 角度表为几何估计：四指侧摆/MCP/PIP/DIP，拇指掌面方向/离掌抬起/MCP/IP。没有个人零位、关节轴及机器人映射标定，不能直接当作机器人命令。
- RGB 关键点错误、指尖互相遮挡、背景与手部深度接近时仍可能估错；深度约束不能修复所有二维位置错误。先保持掌心朝前和整手入镜。
- 默认不保存画面或逐帧骨架。原有“保存当前 RGB＋原始深度”仅在手动点击时保存图像与相机元数据，不包含整段动作或个人标定。

## 文件

- `hand_fusion.py`：深度筛选、骨长参考、21 点融合、角度估计和 MediaPipe 接口。
- `depth_camera.py`：相机采集、对齐和本机 HTTP；`--hands` 开启识别。
- `prepare_hand_model.py`：官方模型准备与 SHA-256 校验。
- `index.html`：RGB/深度覆盖、双骨架对照、质量和角度表。
- `test_hand_fusion.py`：合成数据回归；实测记录见 `VALIDATION.md`。

实现依据：[MediaPipe Python 文档](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/python)、[RealSense 反投影说明](https://github.com/realsenseai/librealsense/wiki/Projection-in-RealSense-SDK-2.0)。融合约束和阈值是本项目实现，不是官方提供的关节深度精度保证。
