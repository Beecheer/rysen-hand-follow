# D435 基础验证

日期：2026-10-20。

后续 D435 已接入个人标定、URDF 解算和 SDK 控制主链，主入口为 Start-DepthFollow/8090；本工具继续作为共享采集/融合实现及独立诊断。全链路证据、当前运行状态和实机验收范围以 `../hand-tracking/docs/D435-VALIDATION.md` 为准，下文是基础与初版诊断记录。

## MediaPipe＋逐指深度约束初版

- 新增独立手部预览入口 Start-DepthHand；在已有 D435 项目中通过 `--hands` 开启，不连接机械手，不改动旧 A/B 标定。
- uv 锁定并实际导入 MediaPipe 0.10.35、OpenCV contrib 4.14.0；已移除重复的 OpenCV headless 提供者。官方 Hand Landmarker 模型已 SHA-256 校验并就绪，运行日志确认 CPU XNNPACK。
- 11 项离线测试通过：原有 5 项加 6 项融合测试。新增覆盖零深度、背景与混合表面拒绝，合成 Z 噪声修正及投影一致性，表面区间不强制中心贴到皮肤，连续模型输入下深度锚点 250 ms 到期，彩深时间差/出界/换人参考重建，四指与拇指角度。
- 前端 JavaScript 和 PowerShell 启停脚本语法检查通过。实际启动融合服务成功，USB 3.2、640×480 双流约 30 FPS，彩深时间戳差一次读取约 9.94 ms。当前没有手时正确显示 NO_HAND，清空三维和角度；后台保持采集。仅 8095 监听，8090/8092/8093 未启动。
- 浏览器实际确认新增标题、来源说明、质量指标、双骨架与角度表已加载。用户真实手部动作、各指深度覆盖、遮挡恢复和精度提升尚待交互验证；不能以合成测试或骨长残差声称真实精度提高。
- 最终版本通过一键脚本实际停止（确认 8095 关闭）并重新启动成功，MediaPipe 随相机正常重新加载。上述约 30 FPS 为没有完整手部入镜时的采集/处理状态，不是已验证的带手融合吞吐率。
- 当前保留 8095 融合预览供用户试用。没有自动保存真实图像、姿态或个人档案。当前表面厚度区间和质量门限为工程初值，操作详见 README-DepthHand.md。

## 当前结果：基础采集已通过

- 用户换用确认支持 USB 3 的 A-C 线后，发现 D435 在 usbipd 中处于 Attached，Windows SDK 无法枚举。detach 后自动重新 Attached；经 Windows 管理员授权，仅对已核对的 `8086:0b07` 取消共享，设备恢复 Windows 访问且报告 USB 3.2。
- 固定 SDK 2.56.5.9235 下，640×480 彩色/Z16 深度双流请求 30 FPS，短测采到 93 个对齐帧，结束时约 30.085 FPS、全画面平均有效深度约 91.61%。深度尺度约 0.001 m/单位，内参已读出；最后一帧深度/彩色时间戳差约 8.60 ms，不宣称已验证硬件同步。
- 试采后 pipeline 正常释放，未保存真实图像。报告在 `logs/probe.json`。这是当前场景短测，不是手部精度或长时间稳定性结论。
- 基础服务实际启动成功，约 30 FPS。通过 HTTP 选择中心像素取得原始 Z、邻域统计和 XYZ；当时背景 Z 约 2.041 m，仅验证接口及反投影输出，不是已知距离精度校准。
- 实际暂停后确认 PAUSED 且相机已释放；恢复后重新取得新鲜帧。正常停止、重新启动成功，最后保留 8095 基础预览供用户使用。五项离线测试及四个 PowerShell 脚本语法检查通过，未自动保存真实图像。

## 先前排查记录

- Windows 识别到 RealSense D435 RGB / Depth 模块，PnP 状态 OK。SDK 能读出设备、固件 5.17.0.10 和支持的流配置。
- 本机 LENOVO 83DG，Windows 检测到 Intel USB 3.20 控制器及 USB 3.0 根集线器。相机父级路径目前为 HS02，SDK 报告 USB 2.1；物理 USB-C 接头不代表已经协商为 USB 3。
- 首次 uv 解析得到 SDK 2.59.1，随后项目固定到与现有固件对应的 pyrealsense2 2.56.5.9235，未升级固件。
- 已试 640×480 RGB/Z16 双流 30 FPS、15 FPS；仍无帧。2.56.5 下分别以 6 FPS 单独采深度与彩色、等待首帧 10 秒，也未收到帧。用户两次调整连接后再次报告 USB 2.1。一次相机软件复位后仍未恢复。
- Windows 相机隐私允许；未发现常见 Viewer / Windows Camera 占用。上述检查不足以断定具体是哪根线、接口或设备问题，需要在实际 USB 3 协商成功后再试。
- 五项离线测试通过：无效原像素与邻域数据分离、反投影及过期检查、边缘/空深度、16 位 PNG 与元数据保存、同源控制/参数验证。测试保存的图像为合成数据。
- PowerShell 启停脚本及浏览器 JavaScript 语法检查通过。尚未取得真实彩色/深度预览、实机距离精度或持续采集成功的结论。
- 实际启动基础工具后，8095 状态接口正确报告帧超时和 USB 2.1，未误报采集成功；随后停止、重复停止均成功，8095 已关闭。当前相机服务已停止，便于用户继续更换线材或接口。
- 无机械手、wslc 或手部识别接入；默认不录制图像。设备枚举记录保存在本机 `logs/devices.json`。
