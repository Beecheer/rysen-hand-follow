# 食指 MCP 单次试动记录与实现

后续已执行更大幅度动作和独立复位，用户确认方向正确，详见 [食指动作与复位记录](README-Index-Cycle.md)。下文保留初次 3° 试动结果。

2026-10-18，在用户授权后执行。使用现有 wslc 镜像中的 SDK 1.4.7、固件 3.2.8；Windows Python 仍由 uv 管理。没有安装普通 WSL，没有启动 Explorer/ROS 后端。

## 实际结果

1. 首次目标为当前食指 MCP +3°，速度参数 3°/s。SDK 拒绝该速度（最低 0.1 rad/s，约 5.73°/s），未产生目标位移；食指已失能。日志保存在 `logs/index-step-rejected-speed.stdout.log` 与同名 CSV。
2. 修正为速度参数 6°/s、加速度参数 10°/s²，位移目标仍为 +3°。只使能食指，只提交一个关节 ID 6 的目标，其他四指未使能。
3. 起点约 0.1245°，目标约 3.1245°。SDK 返回成功时，反馈约 2.0342°，增量约 1.9097°，仍有约 1.09° 误差。程序按自身 0.8° 到位门槛判定未通过并失能，没有自动重试或回零。随后只读反馈约 2.15°，并非已完成 3° 的证明。
4. SDK 速度反馈峰值约 8.81°/s，高于速度参数；本次参数不能被视为已经验证的严格物理限速。尚不能判定来自轨迹跟踪、反馈估计或其他因素，后续需在扩大运动前核对。
5. 用户表示幅度太小、没有看清，因此本次只确认编码器正向变化，未得到实际弯曲方向的人工确认。
6. 测试后重新连接只读桥：设备无故障，五指均未使能。未开放摄像头真机跟随。

保留结果：[SDK 输出](../logs/index-step-trial.stdout.log)、[完整关节反馈 CSV](../logs/index-step-trial.csv)。CSV 是修复前本次实测记录：`elapsed_s` 在提交运动时重置；应按事件分段解释，不可直接当作全程单调时间轴。后续代码已修正此问题。

## 程序范围

源代码 `index_step_trial.cpp`。默认或 `--preflight` 仅连接、加载镜像配套模型并核对姿态，不使能、不运动；`--execute` 才使能食指并发送一个固定目标。

真实 SDK 构建必须使用 `/workspace/rysen_sdk/include`，不能把测试桩 `tests/fixtures/sdk_stub` 放到真实构建的头文件搜索路径。容器中真实程序为 `/opt/hand-follow/index_step_trial`，镜像内配套 URDF 用于本次 SDK 模型加载，与预览 URDF 不完全相同。

执行前必须先断开只读桥并停止其他设备控制器；程序要求五指都未使能，且食指四个反馈角度均在 ±2° 内。当前试动后食指约 2.15°，不满足再次试动前提，不应绕过此检查。再次真实试验需要先明确回零及单独的试验安排，禁止直接扩大幅度以便肉眼观察。

程序监控新鲜完整反馈、设备故障、4 秒总期限、MCP 位移范围及其他关节异常变化；异常或完成时请求食指失能并检查使能标志。它不是经过认证的硬件急停：实际中途故障/断网停止尚未硬件验证，物理停止仍按设备操作方式处理。

## 软件修正与验证

本次发现 SDK 返回成功时，实际反馈仍在变化；立即失能可能过早终止到位过程。代码现已改为 SDK 返回后继续监控反馈，不再发新命令：须进入 0.8° 误差范围并保持 150 ms，最多等待 800 ms，仍受 4 秒总期限约束，否则失能退出。也修正了采样时钟重置问题。

更新后的程序仅完成重新编译和八项模拟 SDK 测试，未再次在硬件上执行，因此不能声称到位问题已经实测解决。模拟覆盖：默认不运动、正常单目标、其他指已使能时拒绝、部分使能失败清理、故障停止、反馈过期停止、SDK 拒绝命令后清理，以及 SDK 提前返回而反馈稍后到位。原有 Windows 35 项测试此前通过。

下一阶段应先验证修正后的到位等待、实际方向与停止行为，确认速度反馈含义；通过后才考虑接入小范围食指摄像头跟随。
