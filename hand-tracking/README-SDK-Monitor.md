# SDK 只读反馈与模拟发送

已另行进行食指单次硬件试动，结果与限制见 [试动记录](hardware/README-Index-Trial.md)。该独立程序未接入本页面，本页面仍是只读反馈和模拟命令模式。

本模式连接左手并订阅反馈，将摄像头目标转换为模拟命令。桥接代码没有使能、修改设备参数、清故障或运动路由。注意：后续单指试验观察到 SDK 1.4.7 的 `Disconnect()` 内部会执行全指失能；所以“没有显式使能调用”不代表整个 SDK 生命周期完全不改变设备状态。启动前不要同时运行其他设备控制程序。

## 环境与启动

Windows 摄像头、解算和页面继续使用 uv 环境。Linux 原生 SDK 来自本机已安装的 `rysen_system:latest` 镜像，与 Explorer 使用的镜像相同。单独的容器 `rysen_sdk_readonly` 使用 `/bin/sleep infinity` 作为入口，再启动只读 Python 桥；不会启动镜像原有 ROS 节点或 Explorer，不安装普通 WSL，不重新导入/拉取镜像。

在 Windows PowerShell 中执行：

```powershell
& D:\Dev\wslc\hand-tracking\Start-HandSdkMonitor.ps1
# 停止摄像头、断开只读 SDK 并停止专用容器
& D:\Dev\wslc\hand-tracking\Stop-HandSdkMonitor.ps1
```

启动脚本拒绝与正在运行的 `rysen_backend` 或 `rysen_explorer` 并用。复用同名专用容器前检查用途标签、镜像、入口和回环端口映射。首次只从已安装镜像创建容器；不删除或重建已有容器。随后上传项目内的桥接源代码，等待左手新鲜反馈，并重启 8090 预览以启用监控模式。当前脚本使用默认摄像头 0、backend auto、左右手校正关；若你使用其他配置，应调整启动参数并核对标定匹配。

页面：<http://127.0.0.1:8090/>。只读桥状态：<http://127.0.0.1:8092/status>。8092 仅发布到 Windows 回环地址，浏览器页面由 Windows 服务读取桥状态；没有向桥开放运动路由，所有 POST 请求均返回 405。

只关闭网页不会释放摄像头，也不会断开 SDK。页面“停止服务”和旧 `Stop-HandMapping.ps1` 只停止 Windows 预览；要完整结束本模式，使用 `Stop-HandSdkMonitor.ps1`。停止脚本先让 SDK 注销回调并断开连接，再停止专用容器；断开时 SDK 会请求全指失能，不代表硬件断电，也不能替代硬件停止措施。

## 页面上的三组角度

- **预览目标**：当前经过识别、标定、滤波和预览限位后的姿态。
- **模拟命令**：以实际反馈为初值，按 20 Hz 生成、位置变化上限 20°/s 的虚拟下发值；不调用 SDK 运动函数。它不是经过硬件验证的轨迹，加速度和碰撞不作保证。
- **实际反馈**：设备回报的关节位置；不因为模拟目标变化而要求设备运动。未使能时也可能有编码器噪声或外力造成的变化。

SDK 关节 ID 由明确名称核对后，按拇指 0–4、食指 5–8、中指 9–12、无名指 13–16、小指 17–20 组织。共 21 个关节，16 个独立目标；联动值依 URDF 计算。内部单位 rad，页面显示度，不使用 MotorId 代替 JointId。

开始测试时点击“恢复 / 重新捕获”，举起左手并缓慢屈伸。两列目标应变化，设备应保持原有状态。暂停、丢手、故障、非有限目标、错误设备身份/关节顺序或超过 250 ms 的关节反馈会阻断模拟命令。恢复后模拟轨迹重新从新鲜实际位置起步，不补发历史目标。监控线程不持有摄像头锁做网络请求，桥异常不会阻塞摄像头采集。

“反馈超出模型限位容差”按 URDF 加约 2° 容差判断，仅标记差异，不修改实际读数。若出现此提示，应在后续运动接入前核对固件零位、模型版本与未使能时的机械姿态，不能通过直接截断实际反馈掩盖问题。软件确认了 SDK 枚举编号；关节的实际运动正负方向仍须在后续单指小范围试验中验证。

## 日志与验证边界

模拟记录追加到 `logs/sdk-dry-run.jsonl`，约每秒一条，包含预览目标、模拟关节数组、实际反馈、SDK/固件版本、设备参数和状态；不保存相机画面。日志只在本机，目录已被 Git 忽略。长时间运行应留意日志大小。容器内诊断为 `/tmp/hand-sdk.log`，默认 SDK 自身也可能在容器 `/workspace/log/` 生成连接日志。

2026-10-18 实测：左手 `192.168.0.102`，SDK 1.4.7、手固件 3.2.8；21 关节反馈正常，初次连接五指均未使能、故障码 0。35 项测试通过，包括原有识别/标定、只读生命周期、POST 拒绝、枚举映射、模拟限速/联动、丢手和过期反馈阻断。状态页的 `motion_calls: 0` 是本程序不调用运动接口的说明，不是设备级全局审计计数，无法监测其他程序发送的指令。

本阶段没有实现运动发送、使能、SDK 内部插值取消或物理急停验证。网页主状态仍描述摄像头跟随，顶层 `robot_connected: false` 是旧预览兼容字段，表示预览不发送真机控制；实际只读连接应查看 `hardware.connected`。后续接入运动前再统一这些状态字段。

实测补充：用户确认预览目标和模拟命令均变化，效果可以。完整停止/断开/容器停止/重启流程验证通过。观察到未使能时 8 个关节反馈超出模型限位容差，主要为负屈伸角度；原始值保持展示，未执行硬件零位调整。进入单指运动阶段前需核对该差异。
