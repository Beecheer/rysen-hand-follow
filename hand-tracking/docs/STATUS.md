## 本次整理发现

离线报告为 `logs/thumb-calibration-audit.json`。只计算已保存的几何参考，不连接设备。

| 检查 | 结果与意义 |
| --- | --- |
| 配置与限位 | 基础签名匹配，参考角度在当前边界内 |
| 保存的总体指尖残差 P95 | 约 44.84 mm；不是实机或独立真值误差 |
| 掌面展开 / 抬起 | 部分目标半径分别超出拇指总链长约 56 / 52 mm，确定不可达；还未计入关节范围带来的额外限制 |
| 自然位 | 预设机器人自然姿态与保存指尖目标偏差约 80.56 mm，参考定义不一致 |
| 对指四组 | 保存参考对各自目标的中位残差约 4.4–6.4 mm，仍需实机验证 |

这表明现有五点相似变换在扩展动作范围时会出现目标外推问题。更多姿态参考能稳定逆解，但不能使机械手达到工作空间之外的位置。角度限幅已经在做；应进一步改善目标定义与任务权重。

## 建议优先级

1. **先做目标一致性与可达性修正。** 统一自然位的指尖和关节姿态参考；标定生成时显示逐动作残差、触限位比例及不可达节点。自由展开优先保持方向和屈伸，对指时再提高相对指尖位置权重。必要时将目标映射到可达区域，避免逆解持续追逐不可能目标。
2. **对比任务型重定向。** 比较位置、骨段向量和指间相对向量的目标，按接近对指的程度连续混合。可参考 [dex-retargeting 官方项目](https://github.com/dexsuite/dex-retargeting) 的 Position / Vector / DexPilot 实现，但需要 Apex URDF、关节顺序与联动适配，不能直接套用其其他机械手配置。
3. **把连续性前移到人手估计。** 固定或稳健估计个人手型，在人手骨架/模型参数上做时序约束，再映射到机械手；结合二维投影约束抑制深度漂移。当前 WiLoR 服务主要输出二维、三维关键点，模型参数需要另行接出并验证。参考 [WiLoR 官方模型实现](https://github.com/rolpotamias/WiLoR/blob/main/wilor/models/wilor.py)。
4. **测量并优化采集至目标的延迟。** 排查手框抖动、裁剪跳动、推理耗时与队列年龄；在当前 RTX 4050 上实测后再决定是否做固定检测间隔、手框跟踪或推理部署优化。更高 FPS 能减小帧间动作跨度，不能自动消除映射偏差。
5. **建立固定离线评测集。** 保存经授权的相同关键点轨迹，比较静止抖动、慢速漂移、往返迟滞、对指模型残差、触限位比例及端到端延迟。需要独立角度/接触测量才能讨论绝对精度，不能只看平滑程度。

优先做 1，并用 5 作为验收，再决定 2 或 3。双目/深度相机可作为后续更换硬件的方向；当前继续围绕自带单目摄像头开展软件优化。
