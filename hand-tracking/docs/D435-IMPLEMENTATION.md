# D435 全链路实施与验收

> 以下为首次逐点融合方案的历史交付。2026-10-20 后续按用户方案切换为两步骨架标定、图像主导四指关节链、近端直接角度拇指及 j3/j4 固定。当前操作与架构以 [D435 说明](../README-D435.md) 为准；旧配置保留，不继续用于新版控制。

目标：D435＋MediaPipe 完成采集、逐指深度融合、个人标定、URDF 解算、SDK 控制全链路，完成后由用户验收。Windows 使用 uv，SDK 复用现有 wslc 镜像。

## 交付要求

1. 同一 D435 RGB/对齐深度源，明确时间戳、有效深度、缺失回退与过期失效；不得静默回退到普通摄像头或固定距离。
2. 独立 D435 八姿态和拇指专项配置，绑定相机与算法版本；保存、加载、重采、备份、重置和错误提示闭环。中立位保存米制骨长，运行中确实用于融合。
3. 深度融合骨架直接用于几何解算和拇指 URDF 逆解，不经单目结构重建覆盖。预览与实际发送共用 SDK/URDF 限位，处理联动及局部无效保持。
4. 复用成熟 SDK 桥、页面心跳、独立目标看门狗、反馈监测。启动失能；人工开始；标定和模式切换先停止，无法确认停止则拒绝变更。无运行时间上限，不增加碰撞求解。
5. 提供一个主页面展示采集质量、个人标定、三维模型、限幅、发送与反馈；启动/停止覆盖相机、桥和容器，重复调用及未知服务保护可验证。
6. 以合成深度和完整模拟 SDK 验证软件数据链与故障路径；真实相机验证采集/释放/恢复；真实设备仅验证连接和失能，不替用户完成动作验收或伪造个人标定。

## 架构

`D435 Camera + HandTracker` → `DepthHandFusion` → `DepthMappingSession` → `DepthCalibrationWizard / ThumbCalibrationWizard` → 几何角度与 `ThumbRetargeter` → `PreviewMapper` → `IndexFollow` → 现有 HTTP 桥 → 原生 SDK worker。

相机和融合实现继续由 `realsense-tools` 提供；主项目从固定工作区路径导入同一份实现。没有第二份深度算法，两个入口不能同时占用相机。D435 配置使用 `d435-current.json` 及 `d435-current-thumb.json`，不修改 A/B 配置。

## 完成证据

已按以上要求核对代码、测试和运行证据，记录在 `D435-VALIDATION.md`。软件架构及贯通验证已交付，用户的本人标定与实际动作验收尚未执行。没有将“预览正常”视为全链路完成，也没有将模拟设备证据写成实际运动结果。
