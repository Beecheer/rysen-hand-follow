# 左手关键点角度映射与三维预览

全手真机跟随模式见 [README-Full-Follow.md](README-Full-Follow.md)：使用 SDK 原有速度参数、无固定运行时限，保留丢手/反馈超时失能。

食指小范围真机摄像头跟随已接入并实测，操作见 [README-Index-Follow.md](README-Index-Follow.md)。该模式需单独启动，并在页面手动开始；普通预览启动方式保持不发送真机运动。

已增加可选的 SDK 只读反馈与模拟命令模式，见 [README-SDK-Monitor.md](README-SDK-Monitor.md)。使用该模式时单独运行现有镜像内的 SDK 桥；默认预览启动方式仍不连接设备。

已扩展到四指侧摆及拇指四个独立关节，覆盖 16 个独立目标关节。Python 环境仍由 uv 管理；当前版本新增 SciPy，用于拇指有界运动学拟合。

使用 MediaPipe 关键点计算四指侧摆和 MCP/PIP 角度，并由拇指关键点拟合官方模型，驱动 ApexHand 左手模型。不做张手/握拳动作分类。完成八姿态个人标定后启用掌面稳定、个人骨长和二维侧摆辅助；旧五姿态配置继续兼容。普通预览仅在 Windows 本机运行，Python 3.11 和依赖全部使用 uv 管理，不连接机械手，也不启动 wslc 服务。标定操作见 [README-Calibration.md](README-Calibration.md)。

## 启动和停止

先关闭第一阶段的 OpenCV 预览窗口，避免两个程序占用同一摄像头。在 Windows PowerShell 中执行：

```powershell
& D:\Dev\wslc\hand-tracking\Start-HandMapping.ps1
```

默认打开 <http://127.0.0.1:8090>，可直接在本机浏览器中打开。首次启动摄像头需要几秒。若端口已被占用，应先停止现有映射预览，或用 `-Port 8091` 换端口。启动脚本使用 `uv sync --frozen`，按锁文件安装依赖，不升级版本。

```powershell
# 特定摄像头 / 后端
& D:\Dev\wslc\hand-tracking\Start-HandMapping.ps1 -Camera 0 -Backend dshow
# 如实际左手在原始识别中显示 Right
& D:\Dev\wslc\hand-tracking\Start-HandMapping.ps1 -SwapHandedness
# 只启动服务，由自己打开浏览器
& D:\Dev\wslc\hand-tracking\Start-HandMapping.ps1 -NoBrowser
# 停止并等待服务退出
& D:\Dev\wslc\hand-tracking\Stop-HandMapping.ps1
```

也可以点击页面“停止服务”，或在前台启动终端按 Ctrl+C。仅关闭网页不会停止摄像头采集。不要与第一阶段预览同时使用同一个摄像头。

## 页面操作

- 摄像头：显示原始识别骨架和左右手类别；镜像只改变显示，不改变计算角度。
- 仅选择校正后标签为 Left、分类分数至少 0.65 且完整入镜的手。分数不是关键点定位精度。
- “左右手校正”用于实际标签与人手不符的情况；切换后暂停，确认左手标签再点击恢复。计算屈伸方向使用原始模型标签所代表的坐标手性，避免镜像驱动造成角度反向。
- 三维模型：左键拖动旋转、滚轮缩放、右键平移；“恢复视角”回到掌面视角。
- 四指表格：“人手估计”在八姿态模式下来自结构拟合、尚未扣除侧摆中立偏置；“输出”经过标定、滤波和机器人约束，均显示为度数，程序内部为弧度。
- 拇指表格：j0 外展、j1 旋转、j2 根部屈伸、j3 MCP 屈伸；显示拟合目标和平滑后的输出。IP j4 根据官方 URDF 跟随 j3。
- 拇指拟合残差是骨段/指尖位置的归一化模型误差，不是识别置信度，也不是实际厘米误差。暂停或无有效手时不显示旧残差。
- “暂停跟随”保持最后目标；“恢复 / 重新捕获”重新收集连续 3 帧有效数据后平滑接入。
- 没有左手时原始角度显示 `—`，不会把右手自动切换过来。

## 映射与约束

1. 用腕部、中指根部、食指根部和小指根部建立掌面参考系。
2. MCP：近节指骨相对各指掌骨参考方向的屈伸平面有符号角度；不是屏幕二维夹角。
3. PIP：相邻三维指骨方向的夹角；DIP 角度可用于后续分析，当前目标 DIP 依 URDF 1:1 随 PIP 联动。侧摆使用近节指骨在掌面内相对手掌纵向的有符号角度，与模型零位的平行手指一致；不再把本来已呈扇形的腕部到指根方向当作侧摆零位。屈伸和侧摆联合分解。
4. 四指 MCP/PIP 一对一角度映射，预览目标范围为 `0–65°` 与 URDF 限位/耦合约束的交集。负的 MCP 伸展角度在当前预览中截为 0；较大弯曲截为 65°。
5. 四指侧摆范围为官方 URDF 与 ±25° 的交集。近节骨段掌面投影长度低于骨长 50% 时保持该侧摆，屈伸继续更新。八姿态模式还检查掌面朝向。
6. 拇指由官方 URDF 的正向运动学驱动四变量有界最小二乘求解。将人手三段拇指方向转换到掌坐标系，按机器人骨段长度重建位置目标；拟合中间点、指尖、末段方向，加入上一解正则项。通常采用上一帧解初始化，种子避开限位边界 0.02 rad，避免从全零位启动时求解停滞。每次求解至多 18 次函数评估（数值雅可比评估另计），位置残差较高时另用范围内部初值求解一次，选择位置残差更低的有效解。
7. 拇指预览使用官方 URDF 各关节完整上下限，允许模型定义的负角度，以免阻断对指姿态。启用标定后，拟合同时考虑校正后的指尖位置；人手拇指靠近某个指尖时，连续增加机器人相应指尖的位置约束。这不是完整的人手姿态恢复，也没有经真机验证；URDF 的矩形限位不代表所有组合都无碰撞。
8. 拇指骨段无效、出画时保持拇指；未标定模式下归一化位置残差大于 0.32 也保持。标定模式容许骨段拟合与指尖约束折中，页面另报指尖目标残差。单个手指末端无效时保持该指；若掌坐标系失效则整手进入丢手处理。模型展示目标姿态，不代表真机反馈，也没有物理碰撞仿真。
9. 时间相关低通滤波时间常数 80 ms，常规连续更新的速度目标上限 90°/s、加速度变化目标 360°/s²。硬限位及暂停/丢手时的姿态保持优先，因此这些数值不构成严格的真机轨迹保证。
10. 拒绝非有限坐标、退化掌面、明显异常骨长、超出画面的关键点以及短时间内手腕位置突变。丢帧不排队补发。

上述直接几何步骤描述旧模式。八姿态模式增加个人掌面模板、固定骨长结构拟合和二维侧摆辅助，人手 DIP 独立估计，机器人 DIP 仍按 URDF 联动。中立位只扣除侧摆偏置，不扣除 MCP/PIP 弯曲，不拟合角度增益。个人标定还拟合拇指位置变换和对指距离参考；无法补回完全遮挡的关键点，也不能让机器人达到结构以外的姿态。

## 丢手和状态

| 状态 | 含义 |
|---|---|
| 等待左手 | 尚未收到有效目标左手 |
| 正在捕获 | 等待连续 3 帧有效关键点 |
| 正在跟随 | 目标角度正常更新 |
| 短暂丢手 | 有效数据年龄达到 200 ms，保持最后姿态 |
| 已暂停 | 丢手达到 500 ms 或手动暂停，需要手动恢复 |
| 摄像头异常 | 摄像头或处理过程出错，查看原因后停止并重启 |

状态超时使用单调时钟；即使采集线程卡住，服务状态轮询仍会检查数据年龄。浏览器断开数据连接时也显示中断状态。恢复不会清零关节然后跳到新姿态，而是从保持的目标逐步接入。

## 模型来源

使用用户指定的 [RysenRobotics/apex-hand-urdf](https://github.com/RysenRobotics/apex-hand-urdf)，固定提交 `3f482caadf61c91e71df6be9e33e2122da768637`。模型和 49 个网格保存在 `assets/apex_left`，许可证及文件来源/哈希一并保留。未使用 SDK 仓库缺失网格的 URDF，也不依赖镜像中的 GLB。

浏览器使用本地 Three.js 0.181.0 和 URDFLoader 0.12.6，不依赖运行时 CDN。完整网格、关节轴、限位和 mimic 关系直接从该 URDF 加载。

## 检查与排错

```powershell
cd D:\Dev\wslc\hand-tracking
uv run --frozen python -m unittest discover -s tests -v
```

- 显示 Left 但不跟随：先看状态，完整放入手掌和全部手指；若已暂停，点击恢复。Left 标签本身不代表关键点已通过有效性检查。
- 模型已弯曲但又冻结：通常是丢手进入暂停；确认手仍完整入镜，再恢复。
- 所有目标都是 0：观察 MCP/PIP 原始值是否出现，确认自己移动的是识别画面中的手。
- 页面打不开：检查启动终端、8090 端口是否占用。停止脚本不要对 Explorer 的 8080 端口使用。
- 摄像头打开失败：关闭 Windows 相机、会议软件和原始预览，检查隐私挡板和桌面应用摄像头权限。
- 调试时可读取 `/api/status`，其中有状态、数据年龄、原始角度和 21 个目标关节。
