## 只需两步标定

使用 USB 3 数据线直连相机，约 0.4–0.8 米，掌心正对相机、整只左手入镜。每步准备 1 秒、采样 3 秒，至少 20 个有效帧。

1. **伸直略分开**：四指自然伸直、略分开，拇指自然展开。测量手掌、各节骨长和拇指参考角度。保持近端拇指可见。
2. **并拢伸直**：保持掌心朝前，四指并拢伸直，拇指不作要求。记录四指侧摆零位。

点击“应用并保存”，再“恢复 / 重新捕获”。无需握拳、四次对指或拇指专项采样。握拳、张合与转掌只作为标定后检查，不写入标定。

新版文件为 `profiles/d435-articulated.json`，schema 4、算法 `d435-articulated-v2`。骨长、并拢零位和拇指直接映射设置原子保存，绑定相机序列号、内参、深度尺度、固件、左右手设置及官方 URDF。旧 `d435-current.json`、旧拇指配置和 A/B 配置保留，不迁移成新标定，不伪造两步样本。保存/重置保留时间戳备份；重采第一步会清除第二步样本。

采样期间页面给出有效帧和拒绝原因。掌面过于侧向、深度不足、手指未伸直或骨长不稳定时需重采当前步。停用标定可比较预览，但不能开始真实跟随。

## 当前算法

采集仍为 D435 640×480 RGB/Z16 对齐双流，MediaPipe 提供 21 个图像关键点。新版控制路径关闭旧的 21 点 Z 优化；原始 MediaPipe 三维只作对照、未标定预览的临时骨长参考，不作为已标定四指的逐帧运动先验。

- **手掌**：优先在腕侧下掌区域采样，避开投影中的末端骨段；先选择一致平面再细化，避免握拳时混合手指表面导致整手拒帧。区域失效时尝试掌部关键点；在掌心朝前的约束下，可由新鲜腕部深度更新平移并沿用朝向。无可靠新深度时仍只允许短时保持。表面到骨架平面采用固定约 6 mm 近似，不是解剖测量。
- **标定骨长**：伸直姿态结合图像射线、可靠关节表面深度与掌面，进行多帧统计。骨长固定后，运行时不随识别噪声变化。
- **四指**：每根指为固定骨长关节链，参数为侧摆、MCP、PIP、DIP。最小二乘以图像重投影为主，深度表面区间与时间连续性辅助；PIP/DIP 不允许反向弯曲。近端射线与骨长约束协助区分 MCP/PIP 弯曲分配。

  相机朝向的表面法向与解剖屈曲法向分开：四指屈曲方向由掌内横纵轴及原始模型左右手坐标约定计算，不能直接用“朝镜头”法向代替。局部拒绝阈值使用与拟合一致的可见性权重，避免被遮挡指尖否决整个手指。页面投影误差仍显示未加权值，不能单独据此判断是否保持。

  快速弯曲后，如果上一帧伸直解明显不符合当前图像，会额外尝试一次弯曲初值；输入运动明显时减弱时间正则，观察误差显著改善的真实大动作不再被固定角差确认挡住。求解使用解析导数减少计算开销。静止时仍保留连续性、异常跳变确认与输出滤波；真正丢手和过期帧仍按原有门限暂停。
- **遮挡**：依据投影重叠和预测关节/测得表面的前后关系推断可见性。可疑点降低图像和深度权重，遮挡表面只提供“关节在后方”的单边约束。它是几何启发式，没有额外训练语义分割模型，不能保证完全遮挡关节的真实角度。
- **拇指**：优先使用点 1（根部）和点 4（指尖）的可靠图像射线与深度，构造相对手掌的三维指尖位置。用两步标定里的中立位置和骨长换算尺度，再根据官方根部轴/偏置作闭式解析角度换算，驱动 j0/j1/j2。它属于解析位置映射，不使用旧的迭代逆解、对指吸附或姿态库。点 2/3 被遮挡时不再阻断可靠指尖；指尖不可见时退回点 1/2/3 近端方向，均不可用时保持。不可达位置按工作空间和关节边界投影/限幅，并在页面提示。

官方机械手拇指 j4 随 j3 联动，所以新版固定的是 **j3 和 j4**，默认 12°。它不等同于只锁住人手的 IP 而保留机械手所有其他自由度。指尖深度驱动根部三个自由度，仍不恢复独立末端屈伸；尺度映射、根部偏置和不可达目标投影也会影响位置精度，不保证精确捏合。

页面“拇指 · 指尖深度与末端设置”可以修改末端固定角度，先应用两步标定才能保存。保存会暂停并请求失能，恢复后检查预览，再人工开始。高级参数 `thumb_direct.neutral_deg` 定义三个近端参考角，`gains` 仅用于近端方向回退（可通过同源 `/api/depth-config` 保存）；默认值不是个人运动范围标定结果。本次掌面和指尖改进兼容现有两步配置，不要求重采。

### 可选：拇指四位置静态标定

已提供自然展开、向食指根部收拢、向小指方向收拢、朝镜头抬起四个静态位置，每步静止采样 3 秒。可先看模型参考姿态，调整根部三个参考角，再采对应的人手位置。四点建立三维位置变换，校正尺度、方向和耦合；末端仍固定。

配置单独保存在 `profiles/d435-articulated-thumb-static.json`，不改写当前两步骨架。支持采样质量提示、重采、保存/加载、启停对比及独立重置；基础骨架、末端角度或限位改变后需重采拇指。详细步骤见 [拇指静态标定](README-ThumbStatic.md)。

## 预览和真实控制

页面左边骨架是 RGB 模型对照，右边显示四指固定骨长解算和拇指近端观测。视频绿点仅表示表面深度邻域通过筛选，不表示测到了正确关节或没有遮挡。骨长固定、低残差及输出平滑都不等于真实角度准确。

输出沿用 SDK/URDF 软件限幅，四指屈伸 0–65°、侧摆约 ±25°；拇指 j1 上限约 28.37°，其余仍按现有限位。联动关节在限幅后同步。没有新增机械碰撞规划、全手应用层限速或运行时限。

单指解算不可靠时优先保持该指；拇指近端无效时保持近端，末端保持配置值。四指屈伸持续失效超过现有 500 ms 门限、全局丢手、通信中断或 SDK 故障仍按既有逻辑暂停/失能。掌面只允许短时沿用至 250 ms，不能无限用旧深度运行。

四指侧摆使用独立的连续性约束，不会因为快速屈伸而一起放松。近节被遮挡或接近朝向镜头、侧摆不可观测时，只保持该指的侧摆，屈伸继续更新；近节重新可见后恢复侧摆。诊断字段 `side_observable` / `side_held` 表示这一状态。该调整不改变拇指解算和已有标定，无需重采。

真实模式仍需：两步标定已启用、当前米制参考哈希匹配、识别有效、SDK 反馈新鲜，再人工点击“开始全手跟随”。启动、恢复识别、应用标定、重新入镜均不会自动使能。标定、左右手切换和拇指配置修改先确认停止；无法确认五指失能时拒绝变更。

## 验收

先用纯预览完成两步标定；缓慢张开—握拳—张开，检查四指方向、握拳连续性、侧摆中立及拇指近端动作。固定角度变化应只改变 j3/j4。重启后应加载新版配置。确认预览后再切换 SDK 模式检查实际方向和暂停。默认不录制画面；配置仅在明确采样并应用后保存。

实现与验证记录：[D435 验证记录](docs/D435-VALIDATION.md)。真实握拳、遮挡和拇指简化映射效果仍需操作者验收。


## 深度掌面与根部弱修正

运行诊断标识为 `rgb_depth_root_correction`。视觉骨架先给出完整姿态，深度修正量缓慢叠加；不重新优化整根手指。可靠掌面需同步、足够平面点、掌心基本朝前、与视觉法向偏差小于 30°。修正取法向偏差的约 30%，最大倾斜 8°；腕深度回退和短时旧掌面不参与新修正。失去可靠掌面时逐渐退回视觉。

近节深度需连续两帧稳定（相邻差小于 8 mm）、局部 sigma ≤4 mm、与其他手指投影无近距离重叠、近节不严重缩短、视觉 MCP 小于 65°。表面加约 6 mm 的中心偏移只作近似；要求测得近节长度与视觉相符（0.75–1.25 倍）、向量差小于 20 mm，才以 15% 权重微调近节方向。这些检查不能证明表面一定属于目标关节，仍需实景验证。

两种修正合计相对原始视觉角限制为 MCP ±8°、侧摆 ±4°，修正量约 160 ms 平滑；掌面约 180 ms 收敛、300 ms 退回。视觉自身运动仍直接进入原有滤波，不用这组时间常数拖慢整个姿态。侧摆不可观测时继续保持该自由度；PIP/DIP、拇指、SDK 限幅和人工开始逻辑不变。三维对照骨架按根部修正旋转整条指链，保留个人骨长和远端弯曲角。

页面显示掌面修正角、是否使用可靠掌面和采用近节深度的手指数；0/4 表示本帧局部深度未满足条件，并不代表全手丢失。无需增加标定动作，先用纯预览缓慢转动手掌、屈伸根部和张并四指，再比较稳定性及根部屈伸／侧摆是否更容易区分。
